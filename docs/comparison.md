# 他ロジバンパーサーとの速度比較

本ドキュメントは、代表的なロジバン PEG パーサーと本プロジェクト(`lojban` v0.9.1)
の解析速度を同一条件で測定した非公式ベンチマークの記録である。

## 測定条件

- マシン: 12 コア Linux(負荷の低い状態)、単一マシンでの簡易測定
- 実装と実行環境:
  - **camxes.js**: 標準文法のリファレンス実装(lojban/ilmentufa)。Node.js v26.4.0(V8 JIT)
  - **maftufa-1.9999.js**: 移植元 zantufa 系の文法(guskant/gerna_cipra 収録)。同上
  - **lojban(Rust)**: 本プロジェクト。release ビルド、公開 API `lojban::parse()`
- 手法: 各文 200 回のウォームアップ後、3000 回解析して平均 µs/回
- 文章(全パーサーが受理するもの):
  - short: `mi klama do`
  - medium: `le gerku poi cadzu ku'o cu batci le mlatu`
  - complex: `mi viska le re ci gerku gi'e cusku do`

## 結果(µs/解析・小さいほど速い)

| パーサー | short | medium | complex |
|---|---:|---:|---:|
| camxes.js(JS) | 1030 | 3101 | 2289 |
| maftufa-1.9999.js(JS) | 1391 | 4669 | 4384 |
| **lojban(Rust)** | **132** | **383** | **429** |
| 比: camxes に対し | 7.8 倍 | 8.1 倍 | 5.3 倍 |

## 解釈上の注意(重要)

この比較は**同じ仕事量の比較ではない**。以下の差異を踏まえて読むこと。

1. **文法カバレッジの差**: camxes は CLL 標準の完全文法(mex・接続詞・無ポーズ
   隣接語など全構文)を扱う。本プロジェクトはコアサブセットであり、常にポーズ区切りを
   要求するなど受理範囲が狭い。狭い受理範囲のほうが一般に高速になるのは当然である
2. **言語・実行環境の差**: V8 JIT 上の JavaScript とネイティブ Rust の差も含まれる
3. **単一マシン・非公式**: 再現用スクリプトは `examples/speed_check.rs`(Rust 側)と
   本ドキュメント記載の node スニペット。数値は環境により変動する

## 測定から得られた副次的発見

- 移植元 zantufa 系のコンパイル済み文法(maftufa-1.9999.js)は、先接続詞
  `ge … gi` を含む文を拒否した(例: `ge mi klama gi do cadzu`)。
  本プロジェクトの移植ではこの構文を受理しており、移植元に対する意図的な
  拡張になっている
- 本プロジェクトが受理しない非標準形(例: 無ポーズ隣接語 `mibroda`)は
  camxes が受理する。逆方向の差もある

## 結論

本プロジェクトのサブセット範囲の文章については、リファレンス実装(camxes.js)の
**約 5〜8 倍**の速度で解析できる。ただし上記の通り機能範囲・実行環境が異なるため、
「優劣」ではなく「設計判断(サブセット+Rust+ポーズ必須)の帰結」として記録するもの。

機能拡張(v0.10〜v0.36)後の同じ条件での再測定。手法は初回と同一
(ウォームアップ 200 回、3000 回解析の平均)。camxes.js は ilmentufa 版を
当日取得して使用。

### 初回(v0.9.1)からの変化

- Rust 側の絶対値は 2〜3 倍程度増加した。これは v0.10 以降に追加した
  時制タグ・先接続・結合 cmavo・mex 拡張などの選択肢増加の代償であり、
  STATUS.md のベンチ記録(v0.31 再計測)と整合する
- それでも camxes.js 対比で 3.6〜4.5 倍を維持している
- 「同じ仕事量の比較ではない」という注意は初回測定時と同様に当てはまる

## バッチモードのスループット参考値(v0.75)

コーパス全 412 行(実文 403 + 既知失敗 2 + 抽出ノイズ若干)を
`lojban --lines -q -f` で一括解析した所要時間は約 13.5 秒
(約 30 文/秒)。非語トークンの拒否に rafsi バックトラックの
100ms 級が含まれるための値であり、正常文のみなら数 ms/文。
